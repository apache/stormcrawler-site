Found a vulnerability? Report it privately to security@apache.org — never in a public forum. The security list is only for undisclosed vulnerabilities and managing their fixes; regular bug reports and other queries cannot be accepted at this address.

How disclosure works

The Apache Software Foundation takes a very active stance in eliminating security problems and denial of service attacks against its products. Every report follows the ASF security process:

01 — REPORT

Privately

You write to the ASF Security Team; the report stays confidential.

02 — FIX

Quietly

The PMC develops, reviews and releases a fix before any disclosure.

03 — DISCLOSE

Publicly

The vulnerability is announced once a fixed release is available.

Threat Model and Security Considerations

StormCrawler is designed to operate in trusted environments as part of a distributed Apache Storm® cluster.

Trusted Configuration

The configuration file used by StormCrawler is loaded during topology submission and is treated as a trusted source. If an attacker is able to modify this file, they would already have full access to the system. Securing the configuration file and the environment in which topologies are submitted is essential.

Apache Storm® Cluster Security

StormCrawler runs on an Apache Storm® cluster, which allows users to submit topologies and execute custom, user-defined code. This model inherently trusts cluster users and assumes they are authorized.

  • Access to the Apache Storm® cluster must be strictly restricted to trusted users
  • Underlying systems should not store secrets or hold elevated privileges beyond those assigned to the authorized users
  • Avoid deploying StormCrawler in multi-tenant environments without strong isolation guarantees

Asking Questions About Known Security Problems

Questions about whether a vulnerability applies to your application, further information on a published vulnerability, or availability of patches should be addressed to the dev mailing list (subscribe · unsubscribe).
